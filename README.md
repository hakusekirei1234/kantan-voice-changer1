# 簡単ボイチェン

[![License: AGPL v3](https://img.shields.io/badge/License-AGPL_v3-blue.svg)](https://www.gnu.org/licenses/agpl-3.0)

Windows 11 向けのリアルタイムボイスチェンジャー（スタンドアロン exe）。

**ライセンス: GNU AGPL v3 or later**（全文は [LICENSE.txt](LICENSE.txt)）
第三者ソフトウェアの著作権表示は [dist/THIRD-PARTY-NOTICES.txt](dist/THIRD-PARTY-NOTICES.txt) にあります。

- **外部プラグイン（VST3 / VST2）をホストできる** — Pitchproof / Graillon 2 / élastique Pitch などを
  DAW なしで使える。内蔵の音質に不満があればこちらへ切り替える
- ピッチ / フォルマントを **-12 〜 0 〜 +12 半音**で独立に調整、それぞれ個別に ON/OFF（内蔵エンジン時）
- 自分の声を聞くモニター出力と、相手に送る出力を**別々のデバイス**に指定可能
- 定常ノイズ（ホワイトノイズ・ファン・マイク自己雑音）の除去、ON/OFF
- 録音 → 聞き返し → **MP3 書き出し**（書き出し後にエクスプローラーでファイルを選択表示）
- リアルタイム**周波数スペクトラム表示**（声の倍音が山として見える）・レベルメーター・実測遅延表示
- ミュートのグローバルショートカット（変更可能）＋ ミュート切替時の通知音

外部ライブラリは JUCE と Windows SDK のみ。MP3 エンコードは Windows 内蔵の Media Foundation を使うため、
LAME 等の同梱は不要。VC++ 再頒布パッケージも不要な単体 exe。

## 使い方

`dist\簡単ボイチェン.exe` を実行するだけ。インストール不要。

### SYNCROOM に音を送る場合

SYNCROOM の「VSTモード」は **SYNCROOM 自身が DAW の中に VST プラグインとして入るモード**で、
外部アプリからプラグインとして呼べるものではない。したがって連携は仮想オーディオケーブル経由で行う。

1. 本アプリの「相手に送る音」に **Yamaha SYNCROOM Driver (WDM)** を選ぶ
   （SYNCROOM のインストーラーが必ず入れるので、追加インストールは不要）
2. SYNCROOM 側：設定 → オーディオ → オーディオデバイスを **WASAPI共有モード** にする
3. SYNCROOM の**インプット**に同じ Yamaha SYNCROOM Driver を選ぶ
4. SYNCROOM の**アウトプット**は自分のヘッドホンを選ぶ

Discord なども同じ要領で、入力デバイスに同じ仮想ケーブルを指定すればよい。

### 遅延について

**遅延はゼロにはならない。** 画面右下に実測値の合計を常時表示し、その数字にマウスを乗せると
内訳が出る。合計だけでは打つ手が分からないため。

遅延は 4 つの合計になる。

| 要素 | 減らし方 |
|---|---|
| 入力バッファ | ASIO にしてバッファを小さくする |
| 音声処理 | 内蔵は 768 サンプル固定。プラグイン使用時はそのプラグインの申告値 + 256 |
| **同期バッファ** | **入力とモニターを 1 台の機器にまとめる（丸ごと消える）** |
| 出力バッファ | ASIO にしてバッファを小さくする |

**最も効くのは同期バッファ**。入力とモニターが別々の機器だとクロックがずれるため、
それを吸収するバッファが必要になり、単独で 20〜30 ms 増える。1 台にまとめると完全に不要になる。
効果がある構成のときだけ「遅延を最短に」ボタンが出るので、それを押せばよい。

実測例（開発機、Pitchproof 使用・ノイズ除去 OFF）:

| 構成 | 往復遅延 |
|---|---|
| 入力 C922(WASAPI 480) + モニター MOTU(WASAPI 512)・別機器 | 約 58 ms |
| 入力 C922(WASAPI 480) + モニター MOTU(**ASIO 128**)・別機器 | 約 47 ms |
| 入力もモニターも MOTU(ASIO 128)・1 台にまとめる | 約 20 ms |
| **入力もモニターも MOTU(ASIO 64)・1 台にまとめる** | **約 6.8 ms** |

最後の行が Cubase 同等の構成。**内蔵エンジンを使うとここに 768 サンプル（16 ms）が加算される**
（PSOLA の先読み 512 + ノイズ除去の STFT 256）。内蔵の 512 は設計上どうやっても消えないので、
遅延を詰めたいなら外部プラグインを使うこと。

**マイクをオーディオインターフェースに繋ぎ替えるのが最も効く。** USB ウェブカメラのマイクは
WASAPI 共有の周期が 480 サンプル（10 ms）固定で下げられず、さらに別機器なので同期バッファ
（13 ms）も付く。この 2 つで 23 ms を占める。インターフェースにマイクを挿せば両方消える。

MOTU 1 台にまとめた状態でのバッファ別実測（Pitchproof 使用・ノイズ除去 OFF）:

| バッファ | 往復遅延 |
|---|---|
| 128 | 約 26.8 ms |
| **64** | **約 24 ms** |

「遅延を最短に」ボタンは、機器を 1 台にまとめたうえで**バッファサイズを実測で総当たりして
最短のものを選ぶ**。ドライバの申告遅延はバッファサイズに対して単調とは限らないので、
計算では決められない（実際に開いて確かめるしかない）。

### プラグインの遅延は「申告値」ではなく実測で扱うこと

★**Pitchproof の遅延は 0 サンプルだった**（VST2 の `initialDelay` 申告も 0、
インパルス応答の実測も 0、正弦バーストの相関でも 10〜18 サンプル＝測定誤差の範囲）。

にもかかわらず、アプリは長らく **遅延 22.8 ms** と表示していた。原因は
`AudioEngine` が `dspLatencySamples()`（＝**内蔵 PSOLA 前提の固定値 512+256=768**）を
そのまま status に入れていたこと。外部プラグイン使用時は `VoiceEngine` 側が
正しい値（ノイズ除去 + プラグインの実遅延）を持っているのに、表示はそれを見ていなかった。

この 16 ms の嘘が「Cubase より遅い」という原因追及を丸ごと誤らせた。修正後は
**同構成で 6.8 ms**（＝デバイスの往復のみ）と表示される。音声経路自体は元から
6.8 ms で、変わったのは表示だけ。

教訓: **プラグインの遅延は申告値を信用せず、インパルスで実測する。**
`_toolchain_test` に測定コードがある。

### DAW と比べて遅延が大きく感じる場合

**同じプラグイン・同じ機器・同じバッファなら、DAW と本アプリの遅延はほぼ同じになる。**
どちらも Pitchproof 自身の 512 サンプル（10.7 ms）とインターフェースの変換遅延が支配的で、
そこはソフトを変えても縮まない。

DAW 側が「遅延ゼロ」に感じられる場合、**オーディオインターフェースのダイレクトモニタリング**
が効いている可能性が高い。MOTU M シリーズの MON ノブは、入力を PC を通さずヘッドホンへ
直接返す。これは変換遅延すら通らないので体感ゼロになるが、**返ってくるのは加工前の生の声**。
加工後の声はその裏で通常どおり遅れて届いている。

確かめ方: MON ノブを完全に「DAW / コンピュータ」側へ回す。それでも遅延を感じなければ
本アプリ側に原因があるので、遅延表示の内訳を見て報告してほしい。

ピッチ / フォルマントを OFF にしても遅延は減らない（切替時に遅延が動くとプチッと鳴るため、
意図的に固定してある）。ノイズ除去も OFF のとき信号経路には残る（同じ理由）。

### 入力チャンネルの選択（オーディオインターフェース使用時は必須）

波形の下、入力レベルの右にある「入力ch」でマイクが挿さっているチャンネルを選ぶ。

オーディオインターフェースは入力を何本も持つ。MOTU M6 は ASIO で **10 本**を出す
（In 1〜6 / Loopback 1-2 / Loopback Mix 1-2）。ここが合っていないと音が入らない。

| 選択肢 | 用途 |
|---|---|
| `In 1`, `In 2`, … | その 1 本だけを使う。**インターフェースはこれ** |
| `先頭2chをミックス` | ステレオマイク（ウェブカメラ内蔵マイクなど）向け |

既定は先頭チャンネル 1 本。**「先頭2chをミックス」を単一マイクに使ってはいけない** —
無音の隣のチャンネルと平均されて音量が半分（-6 dB）になる。

### 表示サイズ

詳細設定 →「表示」タブで **100% / 115% / 130% / 150%** から選べる。**既定 115%**。

拡大は `juce::Desktop::setGlobalScaleFactor()` で行う。**個々のフォント指定は原則いじらない** —
文字だけ大きくすると固定サイズの枠から必ずはみ出す箇所が出るため。全体スケールなら
文字・枠・余白がすべて同じ倍率で動くのでレイアウトは崩れない。切り替えは即座に反映される。

ただし 9〜11 px だった補足文字は等倍でも小さすぎたので、そこだけ 10.5〜12.5 px へ底上げし、
はみ出す枠（スペクトラムの軸ラベル）を個別に広げてある。あわせて遅延表示は
周波数軸ラベルと重なるためスペクトラム右上へ移した。

### 声の特徴表示（既定 OFF・ベータ）

**既定では無効。** 詳細設定 → オーディオ →「声の特徴を自動判別（ベータ）」で有効にする。
判定精度がまだ荒いので、任意で使う機能という扱いにしてある。無効な間は表示ごと隠れ、
解析も一切行わない。

有効にすると、画面左上・タイトルの右に、いま出している声の特徴をテキストで出す。
初期値は `ーーー`。男性寄り=緑 / 女性寄り=ピンク / 中性=グレーで色分けする。
判定は既定 1 秒ごとに切り替わり、**声を止めると最後の判定が残り続ける**
（声を出した直後に目を戻して確認できるように）。次に声を出すと再開する。

**中性（グレー）の判定には語尾に「？」を付ける。** 中性は「男女どちらとも言い切れなかった」
結果なので、言い切っているように見せないため（例: `加工感の強い声？`）。

**★これは学習済み AI ではない。** 「ギャル女声」「セクシー女声」のような様式的な分類は
本来ラベル付きデータで学習した分類器が要るが、このアプリはオフライン・軽量が前提で
学習パイプラインを持たない。実装は音響特徴量からのルールベース判定であり、
位置づけは「音響的な目安」。特徴が明確なもの（低い男声・少女声）ほど当たり、
様式的なもの（ギャル・セクシー）ほど「それっぽい」程度に留まる。

使う特徴量は 6 つ。

| 特徴量 | 中身 |
|---|---|
| f0 | 基本周波数。YIN の CMNDF で推定 |
| formantScale | LPC で求めた F1/F2 から出す声道長の指標（1.0≒平均男性 / 1.18≒平均女性 / 1.35≒子供） |
| hnr | 周期性の強さ。低い＝かすれ・息漏れ |
| brightness | 2 kHz 以上のエネルギー比 |
| variation | 区間内 f0 の標準偏差（半音）＝抑揚 |
| mismatch | f0 から期待される声道長との乖離＝加工感 |

分析対象は**ボイチェン後の声**（変換後・ミュート前）。処理はすべてメッセージスレッドで、
オーディオスレッドには一切触れない。

実装で踏んだ罠（同じ轍を踏まないための記録）:

1. **f0 推定に素の自己相関を使ってはいけない。** 正規化しても短いラグほど足し合わせる
   項数が多くて有利になり、高い方へ引きずられる。実測で 115 Hz のかすれ声が 480 Hz と
   判定された。YIN の CMNDF はこの偏りを累積平均で消すために作られている。
2. **主要 2 次元（f0・声道長）の重みは、色付け次元の合計を必ず上回らせる。** 逆転すると
   「抑揚が大きい女性」が全部「おばあちゃん声」になった。
3. **ジッター（声の揺れ）はフレーム単位では測れない。** 20 Hz のフレーム間差は
   5 Hz 前後のビブラート＝抑揚と区別がつかず、多くの声で 1.0 に飽和した。判定からは
   外してある（値は情報表示に残す）。周期単位の検出を実装したら復活させる。
4. **「加工感」は同じ土俵で点数を競わせない。** f0・声道長の幅を広げて表現しようとすると
   その 2 次元から満点をもらって全部これになる。通常判定の後の差し替えにしてある。
5. **無音判定は -60 dB では緩すぎる。** 部屋の暗騒音を拾って、誰も喋っていないのに判定が
   出た。-48 dB + 周期性 (HNR≥0.55) + 区間の 55% 以上が有声、の 3 段で弾く。

判定に使った実測値は詳細設定の情報タブで確認できる。外れたときはこの数値を見る。

### 画面の表示（周波数スペクトラム）

時間軸の波形ではなく**周波数スペクトラム**を出す。声を出すと基本波とその倍音が
山として並び、何本の倍音が出ているかが読める。ピッチやフォルマントをいじったときに
倍音の並びがどう動くかが見えるので、調整の手掛かりになる。

- 横軸：40 Hz 〜 16 kHz の**対数**目盛り（100 / 500 / 1k / 3k / 10k）
- 縦軸：0 〜 -96 dB（-24 dB ごと）
- FFT 4096 点（48 kHz で 11.7 Hz 刻み）。男声の基本波 100〜120 Hz の倍音が
  1 本ずつ分離して見える最低ライン。これより粗いと倍音が団子になる
- 明るい線が現在値、暗い線がピークホールド（倍音の並びを残像で見せる）

### 入力チャンネル指定の注意（過去に爆音を起こした箇所）

チャンネルを 1 本だけ使う場合でも、デバイスは **0 番からそのチャンネルまでを連続で開く**。
目的の 1 ビットだけを立てた「疎なマスク」で開いてはいけない。バックエンドによっては
開いていないチャンネルぶんの**未初期化バッファがそのままコールバックへ渡され、
フルスケールの雑音（爆音）になる**。C922 で実際に発生した。
選別はコールバック側（`inputChannelPick`）で行う。

### ハウリング保護（聴覚保護）

マイクがスピーカーの音を拾うと、音が回り込んで際限なく大きくなる（ハウリング）。
モニターバス末端のソフトリミッタは -1 dBFS で頭を押さえるだけなので、
**ハウリング時は「-1 dBFS の連続音」がヘッドホンに出続ける**。これは十分に危険な音量。

そのため、リミッタとは別に出力そのものを監視している。

- 出力が 0.85 を超えた状態が**ブロックの 8 割以上・0.5 秒以上**続いたら、
  モニターを **20 ms でフェードアウトして無音**にし、画面に警告を出す
- 機器を変えるか設定を変えると自動で解除され、**200 ms かけてフェードイン**して戻る
- 起動時・機器変更時も必ず 0 から立ち上げる（いきなり全開で出さない）
- NaN / Inf が出力に混ざった場合もここで 0 に潰す（DA で最大音量の雑音になるため）

通常の発声は瞬間的にしかこの水準へ届かないので誤作動しない。

なお、マイクとスピーカーの音響的な回り込みは**デバイスの組み合わせを検査しても検出できない**
（別々の機器でも物理的に回り込む）。出力を監視するしかない。

### 外部プラグインを使う

「② 声を変える」の右側にあるドロップダウンで、内蔵エンジンと外部プラグインを切り替える。

1. 「プラグイン検索」を押す（VST3 フォルダを走査。数秒かかる）
2. ドロップダウンから使いたいプラグインを選ぶ
3. 「画面」ボタンでプラグイン自身の画面を開いて調整する

プラグインの設定は当アプリの設定に保存され、次回起動時に復元される。

**Pitchproof は VST2 のみで配布されている。** VST3 フォルダの走査には出てこないので、
`KVC_ENABLE_VST2=ON` でビルドした版でのみ、VST2 フォルダの走査結果として現れる。

⚠️ プラグインは当アプリと**同じプロセスで動く**。クラッシュするプラグインはアプリごと落とす。
読み込み前に印をディスクに残しているので、次回起動時にそのプラグインは自動で除外される
（詳細設定から解除できる）。プラグイン本体は同梱していない。利用者が自分でインストールする。

## ビルド方法

### 必要なもの

- Visual Studio 2019 以降の **C++ ワークロード**（MSVC v142 で動作確認済み）
- CMake 3.25 以降（4.4.2 で動作確認済み）
- Windows SDK 10.0.17763 以降

### ⚠️ 日本語パスで直接ビルドしてはいけない

JUCE のビルド補助ツール `juceaide` は**非 ASCII パスで確実にクラッシュする**。
CMake が UTF-8 で書いたパスを juceaide が CP932 として読むため、`簡単ボイチェン` が
`邁｡蜊倥・繧､繝√ぉ繝ｳ` に化けて落ちる。

対策として ASCII 名のディレクトリジャンクションを作り、**そちら側のパスでビルドする**。
ファイルの実体はこのフォルダのままで、コピーではない。

```bat
mklink /J D:\vcdev "D:\SynologyDrive\簡単ボイチェン"
```

### ビルド

ビルド中間ファイルは Synology Drive の同期対象外に出すこと。
同期クライアントが obj / pdb を掴むと、コンパイラのバグに見える断続的な LNK1104 / MSB3021 が出る。

```bat
cmake -S D:\vcdev -B D:\kvcbuild -G "Visual Studio 16 2019" -A x64
cmake --build D:\kvcbuild --config Release --parallel 6
```

`--parallel` に数を指定すること。無指定だと論理コア数（この環境では 20）まで並列化し、
JUCE の巨大な翻訳単位でメモリを使い切って `C1060 ヒープの領域を使い果たしました` になる。

成果物: `D:\kvcbuild\KantanVoiceChanger_artefacts\Release\KantanVoiceChanger.exe`

### ビルドオプション

| オプション | 既定 | 説明 |
|---|---|---|
| `KVC_ENABLE_ASIO` | ON | ASIO 対応。無効にするには `-DKVC_ENABLE_ASIO=OFF` |
| `KVC_ENABLE_VST2` | ON | VST2 プラグインのホスト。**公開配布版は OFF でビルドすること**（下記参照） |

## 設計上の要点

### 3系統の独立クロック

入力・モニター出力・送信出力は別デバイスになりうる＝**別々の水晶で走る**。
各スレーブ経路にリングバッファ＋ P 制御のドリフト補正リサンプラを入れてある。
これが無いと数分おきにプチプチ鳴る。詳細設定→情報タブに ppm と xrun カウンタを出しているので、
不具合報告時はまずそこを見る。

入力とモニターが同一デバイスの場合は 1 デバイスとして開き、リングもドリフト補正も通らない
（collapse）。これが最も低遅延な構成。

### ピッチ / フォルマント

相関ロック TD-PSOLA。時間領域処理で FFT を使わないため CPU 約 1%、遅延 512 サンプル固定。
ピッチはグレインの「間隔」、フォルマントはグレイン内の「時間軸」を変えるので、2 つのつまみは直交する。

**dsp.json の仕様からの意図的な逸脱**: 仕様は前後対称のグレイン（半長 h = T0）だが、それだと
1 グレインに必要な先読みが `探索範囲 + 2×T0` になり、120 Hz の男声で約 900 サンプル必要になる。
LOOKAHEAD は 512 しかないため、そのままでは低い声でグレインが不足して破綻する。
先読みを消費するのは**グレインの未来側だけ**（過去側は既にバッファ済み）なので、
窓を非対称にして未来側だけ予算に収めた。結果、遅延 512 サンプル固定のまま 60 Hz まで対応する。

### 構造で守っている保証

- 通知音（ピコ音）は**モニター経路にしかコードが存在しない**。実行時の if ではなく構造で保証。
- 録音タップは DSP 後・ミュート前・通知音前。録音した音＝相手に聞こえるはずの音。
- ミュートは送信のみ無音にし、自分の声は聞こえ続ける（詳細設定で変更可）。
- モニターバス末端にソフトリミッタ。仮想デバイスの選び間違いによるハウリングの最終防壁。

### 実測された遅延について

既定構成（WASAPI 低遅延・入力 480 サンプル / 出力 512 サンプル）での表示は **約 69 ms** だった。
上の表で見込んだ 26〜32 ms より大きい。原因はデバイスが返すバッファ長で、
`[低遅延]` バッジが付いていても IAudioClient3 の最小周期が使われるとは限らない。
詰めるには詳細設定でバッファサイズを下げるか、ASIO を選ぶ。

## 配布前に必要な手続き

- **VST2**: `KVC_ENABLE_VST2=ON` の版を公開配布するのは**ライセンス上グレー**。
  Steinberg は VST2 SDK の新規ライセンスを発行していない。`src/audio/Vst2Host.cpp` は
  Steinberg のコードを含まず ABI 定義を自前で書き起こしたもの（Ardour / LMMS と同じ方式）だが、
  リスクはゼロではない。**公開版は `-DKVC_ENABLE_VST2=OFF` でビルドすること。**
  その版でも VST3 プラグインは使える。
- **ASIO**: 有効のまま公開配布するには Steinberg の ASIO ライセンス同意書（無料・要署名手続き）が必要。
  取得前に配布する場合は `-DKVC_ENABLE_ASIO=OFF` でビルドする。
- **JUCE**: 個人名義・完全無償配布であれば無料枠に収まる。法人名義に変わる場合は要再確認。
- **コード署名**: 無署名 exe は SmartScreen の警告に必ず引っかかる。一般配布するなら
  コード署名証明書は事実上必須。
- **ホットキー**: 単独キー割り当て時に使う低レベルキーボードフックは、
  ウイルス対策ソフトのキーロガー検出に触れる可能性がある。既定では必要なときだけ導入する。
